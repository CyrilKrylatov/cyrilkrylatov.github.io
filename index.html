Août 2019 - maintenant / Développeur front-end, référent front @ ComeUp (ex 5euros.com)

Référent front-end : 7 ans chez ComeUp, 12 ans sur le produit
Marketplace de services (ComeUp). Continuité rare qui m'a permis de piloter le codebase front sur la durée, de refactorer par cycles, et de conduire des changements structurels sans interrompre le delivery. Seul intervenant sur le HTML et le CSS, auteur de la majorité du JavaScript ; le JS écrit par les développeurs back passe par ma code review avant merge. Retour d'expérience détaillé sur mon blog.
Design System interne — conception, implémentation, documentation
Conception et maintenance d'un design system bâti sur Bootstrap 5 : thème Sass unifié (couleurs, typographie, spacing, breakpoints), tokens exposés en custom properties CSS pour permettre la variation runtime, conventions de nommage, composants standardisés à partir des primitives Bootstrap. J'ai également écrit et je maintiens la page de documentation interne qui sert de référence à toute l'équipe.
Industrialisation du framework CSS
Rationalisation de l'arbre d'imports Bootstrap (retrait des modules inutilisés), consolidation des feuilles Sass, découpage par entrées Webpack. Objectif tenu : un CSS livré léger, prévisible, sans redondance ni styles ad hoc.
Sortie progressive de jQuery vers Vanilla JS et Stimulus
Refactoring continu du legacy JavaScript : suppression des dépendances superflues, réécriture en vanilla puis structuration via des controllers Stimulus. Résultat : moins de dépendances, code plus testable, meilleure performance au parsing, découplage HTML/JS.
Trois refontes complètes de l'identité visuelle
Migration du CSS et du HTML à chaque changement d'identité, en continu, sans gel du produit. Chaque refonte a servi à consolider le socle : passage des styles ad hoc à un thème Sass structuré, puis au design system actuel.
Performance et accessibilité, mesurées et non négociables
Suivi régulier des Core Web Vitals sur les pages critiques : chasse aux repaints et reflows, contrôle de la CLS et de l'INP, préchargement raisonné des ressources bloquantes. Mêmes exigences côté accessibilité : HTML sémantique, navigation clavier, gestion du focus dans les composants interactifs (modales, dropdowns), contrastes vérifiés. Perf et a11y sont vérifiées au même titre à chaque évolution front.
Développement continu du produit
Intégration régulière de nouvelles pages et de nouveaux composants, responsive par défaut, sécurisés par du Defensive CSS pour absorber les contenus utilisateurs imprévus.
